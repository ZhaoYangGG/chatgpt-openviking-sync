# 测试与验收

## 自动测试

`npm test` 当前 73 项，使用 Node runner：

- V1 核心/状态库/客户端 35 项。
- P0 采集 13 项、服务实验模拟 3 项、尽力去重决策 8 项。
- V2 消息库/解析 10 项、Worker/manifest 4 项。

全为合成数据和模拟请求，无需凭据，不自动连接服务。fake-indexeddb 是事务模型，不是真 Chrome。合法形状页面伪造载荷风险仍开放，测试通过不代表已经阻止伪造。

## 实机脱敏结论

macOS Chrome 短样本 messages/outbox 为 6/6；第二标签与普通刷新仍为 6/6。独立合成首轮完成后没观察到新的匹配详情；普通刷新后采集两条。

仅覆盖这些样本。不公开真实 ID、时间或原始报告。Windows Chrome、真实分页、全部缓存路径、进程重启、持续性能、生产跨设备同步未验收。

## 浏览器流程

1. 选合成文本会话，记录并暂停已装 V1 的同步设置。
2. 加载 V2，刷新测试标签，检查最后采集时间和数量。
3. 在扩展页面源的 DevTools → Application → IndexedDB 检查数据库，不要误看 ChatGPT 源。
4. 双标签和刷新，确认时间更新、数量不重复。
5. 新轮次分别记录完成后/刷新前/刷新后的事件，不能把页面完成等同于 GET。
6. 多页上滑另测参数、方向及交叠 ID，没观察到就不算验收。
7. 结束关闭测试标签，按原设置恢复 V1。关闭标签不删除测试会话。

## 开发诊断

`poc/chrome-capture/` 为独立只读诊断扩展，有限诊断环和 DOM ID 比对，报告仍可能含隐私，不原样公开。

`src/diagnostics/p0-server-test.html` 是 V1 内的**手动写入实验**。普通测试不会打开它。它复用配置创建合成 Session，先请求关闭相关记忆写入并核验自动 commit 禁用，再追加测试；不自动删除 Session。

仅在授权的隔离服务使用，先核实策略效果，无法证明不会影响生产记忆时停止。HTTP 成功不等于幂等，要回读物理数、唯一来源和正文。已有测试观察到追加重复，不能承诺跨设备零重复。
