# ChatGPT → OpenViking

**让对话成为可持续积累的上下文。**

一个面向 Chrome 的开源 WebExtension 实验项目：把 ChatGPT 会话连接到 OpenViking Session，让对话记录与后续摘要、长期记忆处理各司其职。

无需切换自定义 GPT，也不必每轮提醒模型“帮我保存”。本项目不修改 Prompt、不注入 Memory、不提供 Recall；它不是 ChatGPT 或 OpenViking 官方插件。

> **开发预览，非生产级稳定版。** 仓库同时保留可上传的 **V1 DOM 同步器** 和 **V2 结构化采集预览**。V2 尚未接入上传，且存在未解决的页面载荷真实性风险。请先阅读版本说明和 [安全边界](SECURITY.md)。

## 为什么做这个项目

通过 Prompt 或工具调用要求 AI 记住对话，很难保证每轮执行；不同会话和模型的行为也可能不同。浏览器扩展可以将“采集对话”从模型行为中独立出来。

```text
ChatGPT Conversation
        │
        ├─ V1：DOM → 稳定文本/完整轮次 → 本地队列
        │                                  │
        │                           OpenViking Session
        │                                  │
        │                           服务端归档与记忆处理
        │
        └─ V2：自然详情响应 → 严格过滤 → IndexedDB
                                          │
                                  仅本地预览，未上传
```

V1 能同步，但受页面结构、历史加载和时间推断限制。V2 的方向是使用响应中的真实消息 ID、角色、时间和内容类型，而不是从页面表现推断。

## 两个版本，分别能做什么

| 能力 | V1 · DOM 同步器 | V2 · 结构化采集预览 |
| --- | --- | --- |
| 扩展版本 | `0.1.0` | `0.2.0` |
| 安装入口 | 仓库根目录或 V1 解压包 | `dist/chrome-v2-preview/` 或 V2 解压包 |
| 数据来源 | ChatGPT 已渲染的 DOM | 页面自然发出的详情 GET 响应 |
| 上传 OpenViking | 有，需配置服务 | **没有** |
| 消息身份 | DOM `data-message-id` | 响应 `message.id` |
| 时间 | 观察时间、日期标签或推断 | 保留响应中的原始时间字段 |
| 本地存储 | `chrome.storage.local` | IndexedDB 消息、修订和 outbox |
| 历史要求 | 完整历史前缀检查，可能等待加载 | 仅记录实际收到的响应范围 |
| 新回复采集 | 稳定性/完整轮次判断 | 不保证每轮立即收到详情 |
| 去重 | 单实例队列和远端回读保护 | 当前仅本地消息身份去重 |
| 跨设备零重复 | 不保证；冲突可能停写 | 远端同步尚未交付 |
| 适用场景 | 了解现有同步实现，谨慎试用 | 本地采集验证与开发 |

**当前仅支持 Chrome。** macOS 有样本冒烟记录；Windows 是共同代码的目标平台，尚未完成浏览器实机验收。Safari、Edge、移动端 App 不在本次发布范围。界面主要为中文。

### 已有证据，不夸大保证

- 73 项自动化测试覆盖解析、队列、回读、模拟事务和安全检查；不等同于完整浏览器/服务端验收。
- macOS Chrome 样本：双标签及普通刷新后，真实 IndexedDB 消息/outbox 保持 6/6，没有重复增长。
- 独立合成首轮：回复成功后尚未采集，普通刷新后取得 User/Assistant 两条。它证明本次刷新触发了补录，不证明逐轮实时采集。
- 一个被测托管服务追加了重复的 `source_message_ids`。来源 ID 不等于已经存在的服务端唯一约束，该结果也不代表所有部署。
- 真实分页、Windows 浏览器、持续性能、生产跨设备恢复仍未验收。

公开仓库只包含合成测试和脱敏结论，不包含真实聊天、会话 ID 或原始报告。详见 [测试说明](docs/public/TESTING.md)。

## 快速开始

### 方式 A：使用 Releases 解压包

下载对应文件，**先解压，再加载文件夹**：

| 文件 | 用途 |
| --- | --- |
| `chatgpt-openviking-v1-0.1.0.zip` | DOM 同步器，会上传到自行配置的 OpenViking |
| `chatgpt-openviking-v2-preview-0.2.0.zip` | 仅本地采集，不上传 |
| `chatgpt-openviking-source.zip` | 源码、合成测试、文档、构建脚本 |
| `SHA256SUMS` | 三个压缩包的 SHA-256 校验值 |

打开 `chrome://extensions` → 开启“开发者模式” → “加载已解压的扩展程序” → 选择含 `manifest.json` 的文件夹。

这是解压加载方式，不是 Chrome Web Store 安装包，不自带自动更新。升级时更新对应目录并点击扩展页“重新加载”；不要随意删除扩展数据后假设队列仍在。

### 方式 B：从源码运行 V2

需要 Node.js 20+ 和 npm；扩展运行时不依赖 Node.js。

```bash
npm ci --ignore-scripts
npm test
npm run build:v2-preview
```

在 Chrome 加载 `dist/chrome-v2-preview/`：

1. 使用不含敏感信息的测试会话。
2. 安装/重新加载扩展后，刷新 ChatGPT 标签，让采集桥在页面初始化时安装。
3. 在该会话打开扩展 popup，检查采集数、队列数、最后采集时间和覆盖范围。
4. 再开同一会话的第二标签，检查计数是否保持稳定。

**“本地待上传”只是 outbox 的状态名称，V2 不会因此上传。** “更新状态”按钮只更新 popup，不主动抓取历史。

V2 没有设置页或上传开关，加载即观察匹配请求；如需停止采集，在 Chrome 扩展管理页停用。停用不会自动删除已有本地记录。

### 从源码运行 V1

在 Chrome 加载本仓库根目录，进入扩展设置，填写服务连接信息，保存并测试连接。

V1 默认配置的自动同步、自动整理为开启；未配置服务地址时不会上传。一旦保存有效配置并授权服务域名，符合条件的会话可能开始上传。建议先关闭自动同步检查连接，再按需启用。

同时安装 V1/V2 时，它们是独立实例。**V2 不上传不代表 V1 不上传。** 合成测试前应暂停 V1；不要运行多个 V1 副本同时写同一个 Session。

## 配置 OpenViking

以下属于 V1，V2 尚不使用这些设置。

| 配置 | 说明 |
| --- | --- |
| 自动同步 | 控制 V1 自动发送消息 |
| Server 地址 | 服务提供的 base URL，保留必要路径前缀 |
| API Key | 自己的凭据，仅保存在扩展本地配置中 |
| Agent ID | 可选；需要时通过 `X-OpenViking-Agent` 发送 |
| 认证方式 | 自动、Bearer、`X-API-Key`；自动模式仅在明确 401 时尝试切换 |
| Session 自动整理 | 向服务配置策略，不是插件内定时 commit |

自托管示意：`https://openviking.example.com`，仅占位，不是本项目提供的服务。远端请使用 HTTPS，HTTP 仅考虑用于本机测试。

代码针对火山引擎公共服务端点有专门适配：

```text
https://api.vikingdb.cn-beijing.volces.com/openviking
```

不要追加 `/api/v1`、`/health` 或 Session 路径。实际接入条件、地区、权限与版本兼容性以你的服务和官方文档为准。

连接检查成功不代表全部接口兼容。V1 需要创建/读取 Session、追加消息、回读当前与归档 JSONL 等能力；权限不足不能靠反复重试解决。

### 自动整理不等于上传后马上生成记忆

下表是**本仓库 V1 当前发送的默认配置**，不是对所有 OpenViking 部署默认行为的保证：

| 参数 | 值 |
| --- | --- |
| `pending_token_threshold` | 10000 |
| `message_count_threshold` | 20 |
| `idle_timeout_seconds` | 86400（24 小时） |
| `keep_recent_count` | 2 |
| `min_commit_interval_seconds` | 60 |

前四项可在高级阈值调整；当前 UI 保存时最小提交间隔固定 60 秒。插件写入策略，计时、commit、归档和记忆处理由服务端执行，具体触发与状态取决于部署版本。关闭自动整理不等于关闭消息上传，也不会删除已有记忆。

只有 `messages.jsonl` 不一定是错误，它可以是尚未归档的当前日志。是否进入 `history/archive_*`、是否生成记忆，应结合服务策略和任务判断，插件不伪造目录结构。

参考：[Session API](https://docs.openviking.ai/zh/api/05-sessions) · [火山引擎文档](https://docs.volcengine.com/docs/84313/1860732?lang=zh) · [项目架构](docs/public/ARCHITECTURE.md)

## 会话、消息与去重

一个 Conversation 对应一个 Session。V1 规范化会话 ID 后构造 `chatgpt_<conversation_id>`，来源消息身份为：

```text
chatgpt:<conversation_id>:<message_id>
```

标题、正文、模型和设备 ID 不进入来源身份；其变化不能直接当作全新消息。

- **V1**：持久写入意图、累计水位校验；结果未知时回读当前/历史 JSONL，不直接重发。严格历史前缀或正文检查失败时可能停写。
- **V2 本地**：唯一键 `[scope, conversationId, message.id]`，消息/outbox 原子写入。元数据变化不重新入队；同 ID 正文变化保存修订、隔离该条。
- **跨设备**：IndexedDB 事务只保护同一扩展的数据空间，不是分布式锁。两台机器可能同时写同一来源 ID。

计划中的 V2 上传使用写前回读、写后确认和不确定结果恢复，检测重复后标记、不无限补写。**这些上传行为尚未接入 V2。**

## 时间与顺序

V1 不能从 DOM 保证拿到真实创建时间，可能使用观察时间、日期分组或保序推断。不要把其每个 `created_at` 都当作精确事件时间。

V2 保留响应 `create_time` / `update_time` 数值及十进制表示，缺失保持未知。“原始”指源响应字段，不代表独立验证过服务器时钟，也不提升源数据自身精度。

消息按返回数组和首次观察序列处理，**不按 UUID 或时间排序**。真实时间不能单独重建全部分支。先观察的新页和后补录的旧页也不等于完整线性历史。

## 隐私与权限

| 权限/数据 | 用途 |
| --- | --- |
| `chatgpt.com` 内容脚本 | 只在目标站点采集 |
| `activeTab` | popup 识别当前会话 |
| `storage` | 配置、状态和队列；V2 正文使用 IndexedDB |
| `alarms`（V1） | 后台恢复与重试 |
| 可选 HTTP/HTTPS 主机权限（V1） | 保存设置时申请所填服务 origin，清单范围广为支持自托管，并非自动授权所有站点 |

- 没有项目运营方遥测、广告或分析端点；V1 目的地是使用者配置的服务。
- API Key 不注入 ChatGPT 页面，但扩展本地存储**不是加密保险箱**。
- V2 不读取 Token/Cookie、不主动请求历史、不使用 `chrome.debugger`、不解析 SSE。
- V2 隐私标志必须明确满足过滤规则才入库；隐藏/内部正文不作为对话记录，未知类型标记未支持。此规则不防恶意页面伪造隐私字段。
- 本地正文可能随卸载/清理扩展数据丢失，不能当作唯一档案；删除本地数据也不会删除远端记忆。
- “无正文诊断”仍可能带标题、ID、精确时间、模型等，不能原样贴公开 Issue。

## 开发、测试与打包

```bash
npm ci --ignore-scripts
npm test
npm run validate
npm run build:v2-preview
npm run package:release
```

`fake-indexeddb` 仅为开发依赖，不打进扩展。运行时代码使用浏览器能力，没有第三方运行时框架。

发布脚本只导出白名单源码，生成两个浏览器包、源码包与校验值，默认位于 `dist/release/`。目标已存在时拒绝覆盖，可改用：

```bash
node scripts/package-release.mjs --output dist/release-check
node scripts/audit-public.mjs dist/release-check/source
```

扫描检查文件清单、本机路径、凭据特征、邮件/会话 ID、PNG 元数据等，不能替代人工复核。只从通过审计的 `source/` 发布，不要对包含私人研究的开发目录直接 `git add .`。

```text
src/
  content/       V1 DOM 采集
  capture/       V2 bridge / relay / parser
  background/    同步器、客户端、IndexedDB
  options/       V1 连接/整理策略设置
  popup/         两个版本的状态界面
  diagnostics/   手动服务实验（非普通测试流程）
poc/             只读诊断、尽力去重决策原型
test/            合成自动化测试
scripts/         构建、校验、审计和打包
docs/public/     对外文档
```

开发诊断页可能创建服务端合成 Session；普通安装/测试命令不会执行它。不要在生产实例随手运行，先读 [测试隔离要求](docs/public/TESTING.md)。

## 常见问题

### V2 的待上传数增加了，服务端为什么没有消息？

V2 没有上传功能。这个数字是本地队列，不是正在运行的网络任务；不要直接把预览数据库绑定到生产上传器。

### 回复生成后 V2 没增加？

目前只观察自然详情 GET，不读流式回复。页面可能没有重新请求详情或使用缓存。普通刷新在一个样本中触发补录，不保证补齐所有历史；popup“更新状态”不抓新消息。

### V1 一直等待完整历史？

历史前缀必须可验证。上滑加载有时有帮助，但虚拟列表、分支或选择器变化也可能导致等待。不能靠伪造时间、跳过检查宣称顺序正确，更不要直接删除远端 Session 绕过提示。

### 连接测试 404？

先检查 base URL 和路径前缀。反向代理、自托管路由或版本差异可能造成 404；401/403 则检查认证与权限。公开反馈只提供脱敏后的状态码和路径形状。

### 发现重复或历史冲突？

暂停上传并备份日志，核对来源、顺序、正文。不要清空本地状态后盲目重传。重建 Session 有数据风险，由使用者在理解备份恢复后决定；扩展不自动删除旧 Session。

### 为什么只有 text？

`multimodal_text`、语音、图片、附件、Canvas、`thoughts` 不能因为页面能显示就视为普通文本。只接纳已验证类型，不以静默丢内容换取“全部成功”。

### 会不会越用越卡？

V2 移除了 V1 全页观察/定时扫描路径，采用白名单响应和增量写库，并限制体积、并发与队列。但 JSON 解析、复制流、存储仍有成本；没有长期性能或 Windows 实机结论，不能承诺绝不卡顿。超限应明确失败，不静默截断。
