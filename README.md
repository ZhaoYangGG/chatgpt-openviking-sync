# ChatGPT → OpenViking

**正常聊天，持续积累上下文。**

面向 Chrome 的开源浏览器扩展：被动观察 ChatGPT 自然返回的会话详情，将已采集的纯文本消息同步到 OpenViking Session。使用源消息 ID 和源时间，提供持久队列、回读对账、失败恢复与尽力去重。

不需要自定义 GPT，不修改 Prompt，不读取登录 Token/Cookie，不主动抓取全账户历史。

> **V2 0.2.2 · 功能完整的测试版。** 已接通采集、配置、上传、恢复与状态链路；“完整”指这一功能链路，不代表完整历史、逐轮实时或跨设备绝对零重复。非 ChatGPT/OpenViking 官方产品。安装前阅读 [安全说明](SECURITY.md)。

## 功能

- 一个 Conversation 对应一个确定的 OpenViking Session。
- 接纳已验证的 text User 与最终 Assistant，保留原文和源顺序。
- 直接使用 `message.id`、`create_time`，不从 DOM 推断消息时间。
- 保留 JSON 时间数字文本，转换 ISO 时间时保留小数部分。
- IndexedDB 原子记录消息、修订及 outbox；刷新/双标签交叠不重复入队。
- 写前读取当前与归档日志，排除已存在来源；写后回读确认，不依赖“数量刚好增加 N”。
- 持久写入意图、指数退避及后台每分钟恢复；结果不明时先核验，不立即重发。
- 远端重复可见，不无限补写；同 ID 正文冲突按消息隔离。
- 配置服务与自动整理策略，默认不上传；使用者明确开启。
- 页面转发使用文档绑定的 HMAC、序号和防重放校验，拒绝普通未签名/篡改消息。
- API Key 留在扩展可信上下文，网络请求由后台发出。

### 不承诺的事情

- **不是全账户/全历史备份。** 只同步自然详情响应实际覆盖的范围。
- **不是逐轮实时采集。** 没有 SSE；页面可能不在回答结束后重新 GET 详情。
- **不是服务端原子幂等。** 跨设备仍有并发竞态，采用尽力去重。
- **不支持所有内容类型。** 语音、图片、附件、Canvas、multimodal_text、thoughts 等尚未支持。
- **不防御已被攻陷的页面。** MAIN world 与页面共享环境，签名不是 ChatGPT 服务器认证。
- 当前仅支持 Chrome；Windows/macOS 使用同一代码，浏览器实机覆盖与持续性能仍需扩大。CI 系统测试不是浏览器验收。

## 工作方式

```text
ChatGPT 自然详情 GET
        ↓
文档绑定的签名采集桥
        ↓
后台验签 → 严格解析 → 源时间/身份
        ↓
IndexedDB 消息、修订、持久 outbox
        ↓
远端当前/归档 JSONL 对账
        ↓
只追加缺少的消息 → 回读确认
        ↓
OpenViking 按策略归档、摘要与记忆处理
```

扩展不显式调用 commit，不伪造 archive 文件。完整源对话、会话摘要和长期记忆是不同层次，上传成功不等于记忆提取已完成。

## 安装

### 使用发布包

从仓库 Releases 下载对应版本的 `chatgpt-openviking-v2-<版本号>.zip`（以实际已发布资产为准）；开发中的版本可从源码构建：

1. 解压到固定目录。
2. 打开 `chrome://extensions`，启用开发者模式。
3. 选择“加载已解压的扩展程序”，选中含 `manifest.json` 的目录。
4. 打开扩展设置，填写连接信息。
5. 确认旧上传器已停止、理解页面信任边界，再开启自动同步。
6. 保存并测试连接，然后刷新一个非敏感测试会话。

另有 `chatgpt-openviking-source.zip` 和 `SHA256SUMS`。源码发布根目录默认安装 V2，不需要再安装 V1。下载后先解压，不要将 ZIP 本身交给“加载已解压的扩展程序”。

解压加载不自带自动更新；更新目录后需在 Chrome 扩展页重新加载，并刷新目标标签。不要随意清除扩展数据，未发送队列可能因此丢失。

### 从源码构建

需要 Node.js 20+ 和 npm，扩展运行时不依赖 Node.js：

```bash
npm ci --ignore-scripts
npm test
npm run build:v2
```

加载 `dist/chrome-v2/`。完整 V2 清单为 `manifest.v2.json`；旧 V1 和仅本地预览的清单只为历史实现与回归测试保留，不是推荐安装入口。

## 配置

| 设置 | 说明 |
| --- | --- |
| 自动同步 | 默认关闭；开启后才发送已采集消息 |
| Server 地址 | 自托管或托管服务的 base URL |
| API Key | 自己的服务凭据，不写入代码或聊天页面 |
| Agent ID | 可选，服务需要时发送对应请求头 |
| 认证方式 | 自动、Bearer 或 X-API-Key；仅在明确 401 时尝试自动切换 |
| 账户命名空间 | 同账户各设备保持一致；不要把不同账户混用 |
| 旧上传器确认 | 必须先停止其他 V1/旧上传器，再勾选 |
| 页面信任确认 | 了解签名不能认证被攻陷页面，再勾选 |
| 自动整理 | 配置服务端策略，独立于原始消息上传 |

服务地址、Key、Agent 或命名空间变化会进入不同本地队列空间。**旧队列不会自动转发到新账户。** 切换回来可以继续处理旧空间；新配置保存后刷新目标会话。原预览版 `preview-local-only` 队列不导入生产上传。

自托管示意：`https://openviking.example.com`（占位域名）。远端要求 HTTPS，本机 HTTP 支持 localhost/127.0.0.1。

火山引擎公共端点适配：

```text
https://api.vikingdb.cn-beijing.volces.com/openviking
```

不要追加 `/api/v1`、`/health` 或 Session 路径。服务版本、权限与可用地区以实际部署为准。连接检查成功不等于所有 Session/文件/Task 接口兼容。

### Session 自动整理

本仓库当前策略默认值，不是对所有部署默认行为的保证：

| 参数 | 值 |
| --- | --- |
| pending_token_threshold | 10000 |
| message_count_threshold | 20 |
| idle_timeout_seconds | 86400（24 小时） |
| keep_recent_count | 2 |
| min_commit_interval_seconds | 60 |

前四项可以在高级设置调整。服务端负责计时、commit、归档与提取；插件只写入策略。更新策略会在后台处理已对账 Session，失败单独提示，不将其伪装为已生效。自动同步关闭时不会继续处理这些后台请求。

只有 `messages.jsonl` 不一定异常，可能尚未触发归档。远端策略、调度器和版本决定何时产生 `history/archive_*`。

参考：[OpenViking Session API](https://docs.openviking.ai/zh/api/05-sessions) · [火山引擎文档](https://docs.volcengine.com/docs/84313/1860732?lang=zh)

## 真实时间的处理

```text
messages[i].create_time 的原始 JSON 数字文本
        ↓
不经浮点乘 1000 的小数转换
        ↓
ISO 8601 created_at（保留源小数）
        ↓
OpenViking 写入 → 回读时间差异检查
```

- 例如合成数值 `1600000000.123456789` 转为 `2020-09-13T12:26:40.123456789Z`，不先缩减为毫秒。
- `create_time` 缺失/无效时隔离该条并显示缺少源时间，不用会话创建时间或本机时间代替。
- `update_time` 同样保留在本地，但不作为创建时间。
- 源时间来自 ChatGPT 返回值，不是独立测量的发送/完成时刻。
- 服务端可能降低存储精度；已确认消息如果回读时间不同，会保留“远端时间差异”提示，不保证所有部署支持所有小数位。
- 不按时间或 UUID 排序；页内用源数组顺序，跨页按首次观察顺序。

本地采集时间另存，绝不冒充消息创建时间。

## 去重与迁移

来源键：

```text
chatgpt:<conversation_id>:<message_id>
```

标题、模型与设备不进入身份。客户端向 V1 复用接口传原始 message ID，避免重复拼接前缀。

### 本地与远端

本地键为 `[scope, conversationId, message.id]`，消息/outbox 在同一事务写入。同一安装内上传串行；两台设备不能依赖本地锁互斥。

写前/写后均回读来源记录，记录物理数与唯一来源数。已有相同来源正文则确认，不再发送；同 ID 正文变化隔离；远端已有重复则标记。累计水位与日志条数不符时重试新鲜快照，不把不完整回读当作发送许可。

比较兼容 V1 的正文空白规范化；本地原文和修订仍保留。跨设备竞态可能生成重复，检测不是自动删除，也不能撤销已有记忆影响。

### V1 升级

- **同扩展身份升级**：相同目的地时可读取旧 Session 映射，旧上传配置会关闭。
- **不同扩展身份安装**：不能读取另一个扩展的设置；需手动配置并停止 V1。默认确定性 Session 名及来源键仍用于对账，不直接重传已有消息。
- 若 V1 使用过非默认 Session 映射，独立新扩展不能自动知道它；应使用同身份升级或先做人工映射核对，不假定已迁移。
- 远端已有的 V1 推断时间不会自动重写，也不会为了修正时间重传同一消息。
- 发现其他 Conversation/未知来源混入当前 Session 时停写并提示身份冲突，避免误写目的地；普通重复或单条正文冲突不会因此冻结所有消息。
- 不自动删除、覆盖或重建远端 Session。

## 隐私与权限

| 权限 | 用途 |
| --- | --- |
| chatgpt.com 主机权限 | 页面采集桥，自动作用于目标站点 |
| scripting | 后台向指定 documentId 注入签名采集函数 |
| storage | 配置/诊断及持久队列；凭据限制于可信扩展上下文 |
| activeTab | popup 识别当前 Conversation |
| alarms | 每分钟唤醒失败/剩余队列处理 |
| 可选服务 origin 权限 | 保存设置时请求自行填写的 OpenViking 地址 |

无项目运营方的遥测、广告或内容接收端点。消息目的地是使用者配置的 OpenViking。

本地存储不是加密保险箱。签名用的临时通道密钥不是 OpenViking Key，不通过页面 postMessage 发送；仍不防御在安装前就被篡改的页面 API 或恶意扩展。

默认不上传，但页面采集可能形成本地记录；停用扩展可停止采集，停用不自动清理历史。卸载/清理本地数据可能丢失未上传内容，删除本地也不会删除远端 Session 或记忆。

隐私标志不明确的响应不入库；未支持内容明确标记。不将“无正文诊断”视为匿名数据，标题、ID、精确时间仍需脱敏。

## 状态怎么看

0.2.2 将状态拆为三个数量：**本机已采集 / 远端已确认 / 等待上传确认**。有冲突或缺少源时间时，被隔离的消息单独提示，不算作已确认，也不会伪造完整历史的进度百分比。

- **等待采集详情**：尚未收到可同步的详情，不意味着会话没有消息。若刚聊完没有新采集，可尝试刷新。
- **已采集，等待上传 / 正在上传核验**：无需通过上滑触发上传，可以继续聊天。
- **已采集内容已同步**：已采集的支持消息通过远端回读确认，不保证完整历史或逐轮实时。
- **上传遇到问题**：队列保留并退避重试；「重试上传」仅处理待确认消息，不是强制重新备份所有历史。
- **历史范围**：只解释最近一次响应的分页标志。报告还有前一页时建议按需上滑；两侧均无更多分页时不要求反复上滑，但也不宣称完整历史已备份。
- **过滤说明**：系统、隐藏、内部、工具和 thoughts 节点与不支持的内容分开统计。未满足完成条件的节点不等同于最终回复丢失。

「刷新页面补录」会先提醒保存草稿并等待生成完成。它仅刷新当前会话，让 ChatGPT 自己发出请求，不主动调用其私有 API，也不能保证刷新必然获得详情。

固定扩展到工具栏后，角标会随状态变化：`✓` 表示已采集范围已确认，数字表示待确认数量，`↑` 表示正在处理或当前响应报告还有更早历史，`!` 表示需要查看提示，`停` 表示暂停。悬停可查看具体原因。角标只读取本地会话摘要，由状态和标签页事件触发，不扫描页面、不读取消息全文；弹窗仅在打开可见时每 3 秒刷新状态。

配置问题、来源冲突、缺少源时间、远端重复/时间差异和自动整理配置异常会独立提示。诊断默认折叠，含会话 ID 等识别信息；分享前仍需脱敏。最近确认时间代表上次确认记录，不是持续在线连接证明。

## 常见问题

### 回答已经结束，为什么没同步？

没有 SSE。ChatGPT 未必自然重新请求详情，缓存也会影响。普通刷新在已有样本中触发补录，但不保证一次补齐全部历史；popup 重试只处理已采集队列。

### 源时间已保留，为什么还有“远端时间差异”？

可能是服务端降低小数精度，也可能是该来源早已由 V1 写入推断时间。插件不覆盖历史，保留源值并提示差异；不会把此差异自动当作新消息再发。

### 404 / 401 / 403 怎么处理？

404 先核对 base URL、代理路径和版本；401/403 检查认证及权限。日志回读权限也是去重前提。公开 Issue 只提供脱敏状态码和路径形状。

### 想换 API Key 或服务？

修改设置会隔离本地空间，避免旧队列被误发到新账户；保存后刷新要同步的会话。返回相同配置可继续原空间。不要清空旧数据后假设恢复机制仍在。

### 出现历史冲突怎么办？

查看冲突类型，先暂停并备份。正文冲突按条隔离，未知来源/目的地身份冲突会停写该会话。不要盲目重建远端 Session；扩展不代替你删除数据。

### 会不会卡顿？

取消全页正文扫描，只观察必要响应、增量写库；限制响应 2 MiB、2 个并发 clone、15 秒读取超时、通知和后台工作量。复制、解析和回读仍有成本，这不是绝不卡顿承诺；需继续扩大长会话和长期性能验收。

## 路线图与贡献

已接通范围同步、真实时间、持久队列、回读确认、尽力去重、迁移保护和状态。后续重点：真实分页/缓存覆盖、Windows 浏览器、长期性能、不同 OpenViking 部署兼容性。

SSE、更多内容类型、Safari/Edge、Memory 注入和 Recall 按后续需求评估，不伪装成已支持。
